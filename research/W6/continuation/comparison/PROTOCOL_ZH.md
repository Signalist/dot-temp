# W6 下一轮可执行比较协议

状态：离线设计，未运行 GPU，未改变远端仓库。固定证据提交：f3cb19f0ffe4ecfdb72a7e57b93e512851bcad50。此协议不把 GPU_ONLY 观测升级为原 W6 的物理验证。

本协议局部阶段名 Q/O/R0/R 与原 W6 的 A–E 工作分支不同，不改写其历史阶段或完成状态。

## 核心选择

先证明当前模型能完成一组真正不同、预先冻结的任务，再测观测开销，最后才比较实际生效的推理引擎配置。推荐候选是原 eager 基线与原生 graph-enabled 执行；它是同工作推理运行时效率研究，不是 cap/burn/DC/PCC 控制验证。当前没有已证实可执行的原 W6 物理候选，J_W6 继续为空。

1. Q：development/calibration 任务质量与自然结束基线，保留 heldout 到 R 首次评估。使用独立质量工作包的 development、calibration、heldout 家族划分，先冻结任务、验证器与停止规则。对所有预定任务报告格式/语义/结束状态，不能只留下通过或恰好落在目标 token 档的题
2. O：公共观测底座 COMMON 与 MIN 对照。两臂使用同一能量端点、输出/结束校验和时钟定义。MIN 仅增加其声明的周期采样与持久日志。这只估计额外观测成本，COMMON 也有开销；不从后续 MIN 数据扣除某个历史百分比
3. R：仅在本机已安装引擎支持且实测证明图捕获/回放生效时，固定比较 eager 与 graph-enabled；两臂均用相同 MIN。完整计入加载、编译/捕获、暖机、任务、恢复、失败与退出。若图未实际执行，记为无有效处理，结束候选比较

## 共同服务合同

保持同一个本地 Qwen2.5-0.5B-Instruct 检查点及 tokenizer 哈希、vLLM/驱动源身份、BF16、temperature=0、seed=17、自然 EOS、相同输入顺序和原始提示词。单请求并发、禁用前缀缓存，不更换模型、不缩短答案、不把重试或被截断输出当完成。保留 1536 新 token 和 120 秒请求防失控上限作为协议设置；它们不是业务 SLO，超限计失败/截断。若任务需要调整上限，只能在 development 阶段统一冻结后再开测试。

源文件 benchmark.json 的 id/family/split/prompt 分别映射为记录的 task_id/source_family_id/split_role/prompt。新增 prompt_sha256 为 UTF-8 原文的 SHA256；完整题目哈希另取 BENCHMARK_FREEZE.json。reference_fixtures.json 仅是验证器测试参考，绝不作为模型输出。推理只接收 task.prompt，不附带参考答案、用例 expected 值或验证器实现。写作机器检查通过仍为 MACHINE_GATE_PASS_HUMAN_PENDING，须冻结且盲于臂标签的内容/体裁人工审核；代码只覆盖允许的解释子集，数学只覆盖答案与逆运算等式，不宣称完整推理能力。

每条记录包含 task_id、domain、source_family_id、split_role、prompt_hash、validator_id/hash、输出及 token 哈希、质量分项、finish_reason、EOS 依据、censored、缺失原因。自然 EOS 与质量合格分开判定；验证器支持范围外的结果记为无法判定，不冒充语义正确。temperature=0 不保证跨配置字节完全一致。若要把差值归为相同计算工作的运行时效率，须进一步核验配对生成 token 序列/哈希一致；若仅质量合同等价但输出不同，只能报告整个配置的质量—成本差异，不能把更短输出的收益归因于图执行，且不得删掉不一致配对。

Q 的 development 可用于改进提示词/验证器，所有见过输出的题永久标注 seen；不得把修改后的题重新叫盲测。calibration 用于排查实现与估计方差。heldout 必须在任何候选结果出现前冻结，整家族隔离，不做行级随机拆分。同一生成器产生的题只能称新生成家族留出测试，不能称外部独立基准。报告所有家族/领域，不混成“72 道独立题”。

没有业务质量门槛时，Q 不捏造“通过率足够高”的标准。若整套存在失败，仍可描述所有任务的质量—成本联合结果；只有预先规定的任务集两臂全部完成并满足验证合同，才能作该有限集合的严格质量匹配效率结论。不能事后挑选两臂都通过的子集作主结论。

## 能量与时间边界

主报告并列三种边界，禁止互换：

- request：接收提示词/开始模板化，到最终输出可用；另列引擎主机可见 TTFT/e2e。主机输出合并时 ITL 缺失，不能用 TPOT 伪造逐 token 间隔
- cycle：原协议请求前 2 秒、执行/日志/闭合、请求后 2 秒的 GPU 计数器差。固定约 4 秒观测保留并单列，不称纯生成成本，也不盲减 idle 功率
- engine episode/job：最早可读计数器端点起，覆盖模型加载、编译/图捕获、暖机、所有预定任务及失败、日志、恢复、退出。端点前后未覆盖能量必须标未知；不能把 GPU 报告域称整机、电费或 PCC 能量

预先固定部署工作量 H：一遍冻结的 heldout 任务集。主净成本比较为每个新启动引擎完成这同一 H 的总能量差，不能把候选启动代价无限摊薄。可另给其他 H 的模型化摊销敏感性，但不得当成实测。所有任务都计入分子，成功任务数单列；总能量/成功数只是本批综合比值，不是失败后自动重试到成功的期望成本。

记录每臂开始/结束温度、功率、时钟、显存、队列、缓存和退出确认。固定等候与 CUDA 同步不证明热状态相同。使用校准阶段预先冻结的共同恢复/观测规则，所有恢复费用计入。若没有可验证的状态复位，只能报告该执行次序与边界的成本，并给顺序敏感性，不能声称热力学闭合或完整再生循环。

## 试验次数与比较单位

默认采用固定次数，不采用“加样到显著”。质量池 benchmark.json 已冻结为 18 个任务、9 个结构家族，每个 split 6 个任务、3 个家族；同家族两个变体不算独立质量样本。任务数量由该质量池确定，下面是建议设计而非已获资源承诺，也不宣称达到某个精度：

- Q：development 与 calibration 各一遍，共 12 个任务；失败不替换。6 个 heldout 任务在 R 的候选、参数和分析冻结前完全不运行，其基线与候选输出在冻结配对评估中首次采集。若提前查看，则只能标为 seen-reference，不再声称质量泛化盲测
- O：4 个新引擎会话；每个 calibration 任务每种模式一次。COMMON→MIN 与 MIN→COMMON 在会话/任务内平衡，所有次序预先生成。仅为开销诊断，不承诺识别 1% 效应
- R0 兼容性：calibration 集一次完整 eager/graph 配对，确认捕获/回放、闭合和质量；不进入确认样本。失败则停止，不反复换配置直到成功
- R 正式比较：固定 12 个配对块，每块同一 GPU 上先后启动两个全新引擎 episode，6 个 eager→graph、6 个反序，随机排列并先存哈希。每臂执行相同 H，一次/题；不额外重复确定性输出。若平台无法保留同一设备执行两臂，先改写并冻结非配对设计，不假装配对

配对块不是必然独立硬件。记录真实 GPU UUID 哈希和复用；先算块内差，再按实际 GPU 聚类报告，不把请求/token 当独立样本。固定任务集合的估计与对新任务/新硬件的泛化分别说明。设备数太少或单设备时，主要给有限样本差值、逐块结果和顺序敏感性；任何模型区间写明假设，不许把历史 12 会话/8 GPU 的 t 区间当认证覆盖率。

报告每臂全任务合格率、截断/失败率、实际输出一致率、总能量、端到端/TTFT、缺失 ITL、及配对差。没有 SLO/MDE 时给效应量和不确定性，不能宣布业务非劣、显著节能或实时保证。无效/失败尝试都留档；暂停只因源漂移、计量破坏、异物计算、闭合失败或安全问题，不因负面结果补样。

## 候选准入与停止树

当前离线能完成：任务与验证合同、重评分、源审计、协议/分析和数据字段。要执行 GPU，只缺可操作的现有服务器会话/连接与其授权范围的核验；不能自动租新资源。

- 若仅有客户端访问，不能将 sleep、慢读流或延迟转发说成 GPU 控制。留在 Q/O 或描述性模型识别
- 若本机 vLLM 可配置：读取安装版本/源与实际 resolved 配置；确认 eager=False 的原生执行、所用图模式、后端及回放证据，不能只看命令行开关。不升级依赖来强行成功
- 若图候选有效：锁定这一个配置。两臂非预期差异（例如并发、缓存、精度）必须清除或把它命名为整个配置包效应。图编译与内存成本保留，不能归因成单一硬件节能机制
- 若质量或输出合同失败：保留联合成本结果，拒绝严格同质量节能结论；不删题、不降低标准
- 若无有效候选：停止 R，交付质量/观测/成本诊断；原 W6 物理门保持未通过

第二个、仅供以后选择的替代是原生多请求 batching/scheduling。它改变单任务串行目标，必须另定到达轨迹、队列等待、并发、截止/服务目标和完整批次成本；本轮不默认执行，也不能与串行每题成本直接比较成节能率。

原 W6 仍另缺实际执行器授权与响应证据、具名电气边界/校准/同步、真实功率与有用工作配对、EOS 后实际返程/必要 burn 能量、初末状态和 DC/PCC 传递数据。GPU_ONLY 可提供有限输入材料，不能填补这些证据。
