一、不可跨越的边界
1. 原交付只做了 CPU 软件/模型检查。原 gpu_handoff 是采集/分析脚手架，不是已完成的真实 W6 控制器。localhost SSE 客户端的 finish_reason=stop 不能证明自然 EOS；host token callback 不能自动代表 device completion；cap-session 仅下发有界 cap、无工作负载，也不是实际功率轨迹执行器。你必须实现并测试所选 engine revision 的真实事件适配器、取消/排空检查和 policy→actuator 执行桥，才能进入相应硬件确认。
2. 不存在 GPU、模型、本地引擎、仪表、权限或同步证据时，准确标为 BLOCKED/NOT_RUN。mock、模拟波形、旧公开资料、CPU replay 不得改成 MEASURED。不同来源不得拼成“同次实测”；历史已看数据不能重新标为新 holdout。
3. 不购买或租用资源，不创建账号，不任意下载权重/大数据，不假设可用 API key/远程服务；不发送私有 prompt、模型输出、硬件序列号或日志到第三方。不自动 sudo、装驱动/CUDA、改固件、锁频/电压/风扇/网络/安全配置或写电源设置。缺依赖先列出当前已装版本和最小安装方案；未获授权不做环境变更。
4. cap/其他物理控制默认关闭。先取得操作者对“具体设备、独占条件、动作、支持范围内的上下限、温度/错误/时间/冷却阈值、人工急停与恢复”的明确批准并记录引用；不能自行把 operator_reviewed 改 true。任何普通 cap 均不得超过会话原始 cap；恢复原始 cap 是唯一允许的回升例外。权限不足停止，不提权。危险实验、未批准 burn、生产设施激励及带电接线一律不自行做。
5. 保持原始保护机制；“移除 guard”消融不是关闭设备/设施安全保护。越界策略只在明确 SIMULATED 模型测试；物理消融仍受统一外层硬件安全边界约束。
6. 在 finally 中恢复已修改设置并 readback；每次会话开始与结束记录原值。恢复失败立即停止、通知操作者、保持 BLOCKED，不开启下轮。断电、SIGKILL、驱动失联的恢复不能承诺，须有人工恢复路径。不能用新增软件温控轮询冒充独立硬件联锁。
7. 不伪造签字、批准、时间戳、标定证书或原始数据。SHA256 证明字节一致，不证明数据真实/事前冻结/人的批准。冻结需可验证的时间与操作者确认；无外部时间锚时如实标 LOCAL_TIMESTAMP_ONLY，不能写独立时间戳认证。

三、科学合同与允许的结论
资源层级 GPU_ONLY：可记录 NVML 读数域功率/能量、温度/clock、host 可见进度、客户端时延，以及经验证的任务/状态返回。不能由 cap 推 actual p，不能由 NVML 相邻差分推连续 slew，不能给未经标定的 device EOS/物理 burn/PCC 安全发证。此分支仍可报告受限的实测 cap-policy 对比，必须与完整 W6 物理确认分开。
资源层级 GPU_DC：经标定、覆盖所有必要 rails 的同步外部 DC 参考；真实进度/EOS、控制效果、完整恢复的证据齐备，才可评估相应 W6 实现合同。结构 validator 通过不是仪器真实、安全或确定性包络认证。
资源层级 PCC：在 GPU_DC 之外需设施人员确认的真实 PCC、电气拓扑、背景负载、时钟/误差、P/Q/V/I/f、设施许可和阈值，才可做实际 GPU→PCC→网侧研究。GPU、整机 AC、机架 AC 均不自动等于 PCC。没有 PCC 资源则 G01–G04 明确 BLOCKED；模型重放可以继续，但标签为 SIMULATED。

保留原A–E研究检查点，不用它们给硬件层级重新编号：A=新意/先例（F02/F03）；B=理论合同/证明/数值（N01/N02/N03，O01可选）；C=网侧价值合同（N04/G01–G05）；D=执行与真实测量（I01–I11/C04）；E=公平冻结/独立确认/消融迁移（C01/F04/C02/C03/C05/A01/A02/X01–X04）。这些检查点与GPU_ONLY/GPU_DC/PCC资源层级是两套不同维度。

旧理论保留条件边界：完整回零投影可在合同下给实际功率逐时支配；有记忆、变号网核不保证频率峰值下降；精确网侧约束一般会破坏原凸域。固定 actual-power cap 仅是充分安全子类，非全局精确最优。0.05 Hz 是旧模型研究预算，不是监管标准、设施许可或硬件阈值。保留旧 hard-deadline 失败、负收益、网格不足和适用范围；不把成熟 Bellman/凸优化器/支持函数 LP 宣称为新算法。

四、实现缺口，先通过适配器门禁
在工作副本中新建明确版本的 adapters/、controller/、runner/、analysis/、tests/；文件组织可随仓库调整，但最终入口和数据合同须稳定。
1. Engine bridge：固定 engine commit、模型/tokenizer hash、n=1、单请求/单并发及输出语义；读取累计 token IDs，delta 输出须查重累计；保存 request_id、prefill/decode、context/KV 位置、stop token/rule、finish_reason、max_tokens、sampling seed。自然 EOS 须核验真实 EOS token 与停止规则；length/cancel/timeout/error/stop_rule/unknown 属不同删失类别。服务端超时不等于已取消，实现官方支持的 request cancel hook 和 queue drain 验证，失败后不能立即运行下一请求。
2. Device timing：按实际 engine 执行路径记录 useful token/kernel 完成，在正确 CUDA stream/event 域建立到 host monotonic 的变换；分别保存 true_eos、engine/controller 可见、客户端可见、命令 issue/return、physical effect。不要用 host callback 冒充 device。逐 token 同步可能扰动性能，应做有/无插桩 A/B；无法达到需用的时间界，就降级为 host-visible 描述，不能强行通过门禁。
3. Controller bridge：从已交付理论/CPU实现提取 W6 policy 状态、工作坐标与终态，定义只读取当下已知信息的 observe→decide→actuate 接口；落地到已批准动作，记录 target actual p、requested/configured/enforced cap、实测 actual p 和命令延迟，说明离散更新/饱和/滞后/跟踪误差。不能把 W6 p(t) 数列直接写进 cap 字段当作物理实现。若只有 cap actuator，先识别 cap→actual-power 可达域及响应，再判定是否存在满足合同的可执行策略；失败应报告 REALIZABILITY_FAIL。
4. Burn/recovery：确认终端后额外功率能否以批准、隔离、可量化的方式实现；不能自动启动 dummy/stress load，不得把下一个真实任务计为前一任务恢复。无物理 burn 时，原依赖 burn 的合同不可部署；可另建明确受限/近似策略合同，但必须新冻结、降低主张。
5. 时间/计量：同 boot monotonic ns 算间隔，UTC 仅锚点；保存 sensor 原始时间、query_begin、arrival、clock_id、boot_id、同步前后 marker、slope/offset/drift/latency 误差与 max_gap。禁止为最佳相关性事后平移并称无延迟；保留 reset/乱序/丢样，不能全局排序掩盖故障。
6. 单元/集成/故障测试：无 GPU 的 fake 必须标 SIMULATED/CPU_TEST；覆盖重复/缺失 token、自然 EOS 与截断、迟报、慢流/绝对超时、取消失败、时钟 reset、混 run_id、丢 rail、sensor gap、日志写满/中断、恢复 readback 失败、重复运行/恢复续跑、禁用执行标志时零 NVML/HTTP/写 cap。必须确认新 controller 与真实采集同时运行在同一 acquisition，而非两次数据拼接。


现有接口兼容性不得假定：旧validate_registry强制transfer_axis为device或model_family，且按整设备/模型族拒绝泄漏；没有workload/phase/context或none轴。无transfer研究可以保留真实的device/model_family轴并使用空transfer角色集合，明确不声称迁移；仅字面none轴需扩展。X01或X04等同设备workload/phase/context迁移须使用经过测试的版本化registry扩展/独立协议映射，不伪填新device/model_family标签。旧selected_folders只找root/run_*，evaluate-service要求registry内所有confirmation/ablation/transfer都存在；本计划的嵌套session/run/attempt raw树需实现安全索引/只读派生扁平视图或版本化path registry，核对每个run/attempt身份与hash。扁平视图不得筛掉失败来让原evaluate“通过”；all_attempts始终包含所有失败/缺失。旧evaluate不能处理的缺失只能明确受限，或事前实现经过测试的缺失处理扩展。按阶段评估应显式冻结必需集合和依赖，不能默默忽略缺失run。所有扩展保留旧结构/泄漏/完整性门禁，新增角色冻结、父子hash链接、无transfer、workload-transfer及嵌套路径/一侧失败测试。

六、pilot、预算、统计与事前冻结
1. 先一条短而完整的只读 smoke；确认采集覆盖 idle→warmup→request→EOS/错误→实际返回→matched-state→cooldown 后，才扩大。warmup 单独记录；primary inference 能量边界预先定，whole-capture/加载/warmup 成本另报。
2. I06 起步为一个已选 stratum：3 个独立初始化 session × 至少 5 个安全且实际可区分的功率区域 × 每档每 session 2 次独立 episode，共 30 episodes。安排随机顺序、反向/不同顺序及重新初始化，避免温度/顺序混淆；“3 clusters/30 episodes”如实写，不作 30 iid。达不到五个可达功率区域是可识别性限制，不通过改变 workload 来凑五档。I09 只用预设少量 context/phase/温度 sentinel 证伪标量服务假设；不做巨大全因子扫描。
3. pilot 永久属 development；自然 EOS、固定输出长度、max-token 截断、取消、超时、错误分别保存。预设自然工作量分布/有界支持 M 的来源与适用范围；观察到最大 token 不证明自然有界，截断不等于 EOS。只有条件模型、误差来源和适用域被数据支持，才用来生成 policy；OLS 区间均值/最大残差不等于点态服务下包络或未来 supremum 证书。
4. 从 pilot 的成对 session/cluster 差异、工程最小有意义效应 MDE、QoS/quality 非劣界、计量不确定度、失败预算和可用总时长，制定一次冻结的主确认预算；写明独立单位、每 session block/pair 数、策略数、strata 数、calibration 与 confirmation 数、冷却/标定/失败重试上限、总 GPU 小时/日志量。预算不足应诚实为探索或不确定，不能靠把 token/window 计作独立样本补 N。
5. iid 零失败的 59/299 或多端点 Bonferroni 数字只能在该二元事件与独立性条件成立时用；不是配对节能试验样本量，也不是硬件安全证书。连续主 endpoint 用 cluster-aware CI/预定配对随机化或 cluster bootstrap；请求配对在 cluster 内，重复 prompt/seed 不自动提供独立 session。p95/p99 样本稀少需给不确定度，不能用漂亮分位数掩盖尾部不足。
6. Calibration、confirmation、ablation、transfer 按完整 session/device/model_family 划分。冻结注册含未来 run slots，不能 outcome 出来后换标签；完整设备/模型族留出不是随机拆行。Transfer 无调参评估和 adaptation 后重标定/重新确认分开。

七、比较策略、数值精度与消融
